## 0. 怎么用这份文档

- 每条需求有唯一编号 `FR-模块-序号`。分支名、提交信息、Issue 标题都引用这个编号，比如 `feat(DOC-004): 文档版本历史`。
- **优先级是交付阶段，不是重要性**。P0 也可能是个小功能，P3 也可能很关键——只是现在不做。
- 「验收要点」是**能演示、能测出来**的标准，不是完整测试用例。它存在的意义是防止「写完了但说不清算不算完成」。
- 需求变更不直接改历史条目，而是新增一条并注明替代了谁，同时写一篇 ADR 说明为什么变。

优先级图例：

| 标记 | 含义 | 对应里程碑 |
|---|---|---|
| P0 | MVP，不做就没有产品 | M2 |
| P1 | 有了才像样，技术深度主要在这一层 | M3 |
| P2 | 平台化、智能化 | M4 |
| P3 | 有余力再说，明确可砍 | M5+ |

## 1. 产品定位

**一句话**：给自己和几个朋友用的、支持多人实时协作的文档与知识空间。

**不是什么**（这条同样重要）：

- 不是 Slack / 飞书——不做即时聊天，只做评论和通知
- 不是 Notion 的替代品——不做无限嵌套的数据库视图
- 不是企业内部办公系统——不做审批流引擎、组织架构同步
- 不是商业产品——不做支付、不做多语言全量、不做移动端 App

**为什么是这个**：协作平台天然会长出多租户、权限、实时、搜索、文件、通知、审计这些横切能力，每一块都能对应一组真实的工程问题，而且业务需求你自己天天在用，不会枯竭。

## 2. 目标与成功标准

### 2.1 产品目标

一个人也能用得舒服，两个人以上能明显感觉到「比微信传文件强」。

### 2.2 学习目标

把 JDK 25、Spring Boot 3.5、MySQL 8、Redis、RabbitMQ、MinIO、WebSocket、CRDT、全文检索、向量检索、AI 编排、可观测性、Testcontainers、容器化部署全部**落到真实业务里**，每一项都能说清「为什么用它、不用它会怎样」。

### 2.3 可验证的成功标准

| # | 标准 | 验证方式 |
|---|---|---|
| S1 | 有 3 个真实用户连续使用 2 周 | 审计日志里的登录记录 |
| S2 | 核心接口 P95 < 300ms，搜索 < 500ms | k6 压测报告 |
| S3 | 单文档 5 人同时编辑不冲突、不丢字 | 手动 + 自动化测试 |
| S4 | 从零到部署，一个人能在 30 分钟内跑起来 | README 快速开始计时 |
| S5 | 累计 12 篇以上 ADR | `docs/adr/` 目录 |
| S6 | 关键链路的 trace 能串起来看到 | Grafana/Tempo 截图 |

## 3. 范围

### 3.1 做

文档协作、知识空间、评论讨论、文件附件、全文与语义搜索、通知、审计、AI 辅助、开放 API。

### 3.2 明确不做

| 不做 | 原因 |
|---|---|
| 移动端 App / 小程序 | 投入产出比低，Web 响应式足够 |
| 即时聊天（IM） | 与评论/通知功能重叠，且技术栈是另一套（长连接 + 消息同步） |
| 视频会议 | 完全另一个领域 |
| 表格 / 看板 / 数据库视图 | 会把项目变成「Notion 复刻」，拖垮进度 |
| 支付与订阅 | 没有商业目标 |
| 多语言全量翻译 | 只做中文，但文案外置，留 i18n 能力 |
| 企业级 SSO（SAML/LDAP） | 只做 OAuth2 社交登录 |
| 离线优先 / 本地优先同步引擎 | CRDT 已经够复杂，离线同步是另一个数量级 |

「不做」清单会随着项目推进变长，这是一件好事。

## 4. 角色与权限

### 4.1 角色

| 角色 | 说明 |
|---|---|
| 游客 | 未登录。只能看公开分享的文档 |
| 注册用户 | 有账号，可以创建自己的工作空间 |
| 空间 OWNER | 工作空间所有者，唯一，可转让 |
| 空间 ADMIN | 管理成员、设置、删除内容 |
| 空间 MEMBER | 正常读写 |
| 空间 GUEST | 只读，且只能看被明确授权的项目 |

### 4.2 权限矩阵（空间级）

| 操作 | OWNER | ADMIN | MEMBER | GUEST |
|---|:--:|:--:|:--:|:--:|
| 查看空间内容 | ✓ | ✓ | ✓ | 仅授权项目 |
| 创建 / 编辑文档 | ✓ | ✓ | ✓ | ✗ |
| 评论 | ✓ | ✓ | ✓ | ✗ |
| 邀请成员 | ✓ | ✓ | ✗ | ✗ |
| 移除成员 | ✓ | ✓ | ✗ | ✗ |
| 修改空间设置 | ✓ | ✓ | ✗ | ✗ |
| 删除空间 | ✓ | ✗ | ✗ | ✗ |
| 转让所有权 | ✓ | ✗ | ✗ | ✗ |
| 查看审计日志 | ✓ | ✓ | ✗ | ✗ |

### 4.3 资源级权限

空间角色是**底线**，资源还有自己的规则：

- 文档可以单独授权给某个人（覆盖空间角色）
- 文档可以设为「空间内公开」或「仅项目成员可见」
- 分享链接可以脱离成员体系（带过期时间和密码）

> 实现上是 RBAC + ABAC 的混合：**角色决定能做什么，资源属性决定能对哪个对象做**。这正是权限系统最容易写错的地方，也是要重点练的。

## 5. 功能需求

### 5.1 账号与身份（AUTH）

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|:--:|---|
| FR-AUTH-001 | 邮箱 + 密码注册 | P0 | 重复邮箱返回 409；密码 < 8 位返回 400；密码用 Argon2id 或 BCrypt 存储 |
| FR-AUTH-002 | 邮箱验证 | P0 | 注册后发验证邮件；未验证不能邀请他人；链接 24 小时过期 |
| FR-AUTH-003 | 登录与失败锁定 | P0 | 连续 5 次失败锁定 15 分钟；锁定期间返回 429 且不泄露账号是否存在 |
| FR-AUTH-004 | JWT 双令牌 | P0 | access 15 分钟、refresh 7 天；refresh 一次性轮换，重放旧 token 直接吊销全部会话 |
| FR-AUTH-005 | 登出与全设备登出 | P0 | 登出后旧 access token 在 Redis 黑名单中立即失效 |
| FR-AUTH-006 | 修改密码 | P0 | 需要旧密码；成功后其他所有会话失效 |
| FR-AUTH-007 | 忘记密码 / 重置 | P0 | 邮件链接一次性、30 分钟过期 |
| FR-AUTH-008 | 个人资料 | P1 | 昵称、头像、时区；昵称 2–32 字符，支持 emoji |
| FR-AUTH-009 | 会话与设备管理 | P1 | 列出所有活跃会话（设备、IP、最后活跃时间），可单个撤销 |
| FR-AUTH-010 | OAuth2 社交登录 | P1 | GitHub 登录；同一邮箱的账号自动关联而非新建 |
| FR-AUTH-011 | 两步验证（TOTP） | P2 | 绑定 Google Authenticator；提供 10 个一次性恢复码 |
| FR-AUTH-012 | 账号注销 | P2 | 软删除 + 30 天冷静期；期间登录可恢复 |

| FR-WS-004 | 成员管理 | P0 | 改角色、移除成员；OWNER 不能被移除，只能先转让 |
| FR-WS-005 | 转让所有权 | P0 | 只有 OWNER 可操作；转让后自己降为 ADMIN |
| FR-WS-006 | 空间设置 | P1 | 名称、描述、头像；修改名称不改变 slug |
| FR-WS-007 | 配额 | P1 | 成员数、存储空间、AI Token 三个配额；超限返回 402 并提示 |

### 5.6 实时协同（RT）

技术含量最高的一块，也是这个项目最值得炫耀的部分。

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|:--:|---|
| FR-RT-001 | 协同连接 | P1 | WebSocket 连接需带 JWT；令牌过期自动重连换新 |
| FR-RT-002 | 在线状态 | P1 | 显示谁正在看这篇文档（头像列表） |
| FR-RT-003 | 光标同步 | P1 | 看到其他人的光标位置和选区，颜色区分 |
| FR-RT-004 | 并发编辑 | P1 | 10 人同时编辑同一段落不冲突、不丢字；基于 CRDT |
| FR-RT-005 | 断线重连 | P1 | 断网 5 分钟后重连，补齐全部改动；不接受「刷新一下就好了」 |
| FR-RT-006 | 文档快照 | P1 | 每 100 次操作或 5 分钟生成一次快照；重启后能从快照 + 增量恢复 |
| FR-RT-007 | 编辑冲突提示 | P2 | 同一块被两人以不兼容方式修改时提示，而不是静默覆盖 |

> **验收 FR-RT-005 的方法**（这条最容易糊弄过去）：开两个浏览器，一边编辑，另一边用开发者工具切到 Offline，编辑 20 秒后切回 Online，检查文字是否完整。

### 5.8 搜索（SRCH）

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|:--:|---|
| FR-SRCH-001 | 全文搜索 | P1 | 标题 + 正文；中文能搜到（不要求完美分词） |
| FR-SRCH-002 | 相关性排序 | P1 | 标题命中权重高于正文；完全匹配优先 |
| FR-SRCH-003 | 关键词高亮 | P1 | 结果片段中高亮命中的词 |
| FR-SRCH-004 | 筛选 | P1 | 按空间 / 项目 / 作者 / 时间范围 / 内容类型过滤 |
| FR-SRCH-005 | 搜索建议 | P2 | 输入时自动补全文档标题 |
| FR-SRCH-006 | 语义搜索 | P2 | 「怎么邀请同事」能搜到《成员管理指南》这类不含关键词的文档 |
| FR-SRCH-007 | 混合排序 | P2 | 关键词得分与向量相似度加权融合，权重可配置 |

> 演进路径写死在这里，避免一上来就堆组件：**MySQL 全文索引（ngram）→ 不够用换 OpenSearch → 再加向量**。每一步都要有数据支撑（查询延迟、命中率），而不是拍脑袋。

## 8. 里程碑

| 里程碑 | 内容 | 出口条件 |
|---|---|---|
| **M0 环境** | JDK、Docker、MySQL、中间件 | 4 个容器 healthy，MySQL 可连 |
| **M1 地基**（2 周） | 多模块工程、Modulith 边界、Flyway、CI、OTel、Testcontainers、ADR×3 | `./mvnw verify` 全绿；trace 能看到一次请求的完整链路 |
| **M2 MVP**（6 周） | AUTH 全量 P0 + WS + PRJ + DOC 基础 + FILE 基础 + AUD 基础 | **只交付 API**（用 `.http` / curl 验收，不做页面）：注册 → 建空间 → 写文档 → 传附件全链路可用；第二个人能通过 API 读到文档 |
| **M3 V1**（6 周） | CMT + RT + SRCH + NOTI | 两人能同时编辑不冲突；搜索能搜到中文；@提及能收到通知 |
| **M4 V2**（8 周） | AI + OPEN + ADMIN | 文档问答带引用；API Key 能调通；后台能看运行数据 |
| **M5 纵深**（4 周） | 压测、缓存优化、混沌演练、备份恢复 | 压测报告 + 一次有数据的优化 + 一次恢复演练 |
| **M6 平台**（4 周） | k3s 部署、灰度、拆一个服务 | 拆出去的服务全链路 trace 可见 |

> **前端节奏（方案 A，2026-10-25 决定）**：M1、M2 只做后端 API，用 `.http` 文件验收；
> 前端 Vue 3 + Vite 从 **M3** 开始，一次把登录 / 空间 / 文档列表 / 编辑器做完。
>
> 理由：先把接口形状和业务规则定稳，避免前端跟着接口反复改。
> 代价：M2 期间没有可点的界面，所有验收都走 HTTP 客户端——这是**主动接受的代价**，不是遗漏。

**每个里程碑结束时要能回答三个问题**：做了什么、哪个数字变了、如果重来会怎么做。

## 10. 变更规则

1. **新增需求**：直接加进对应模块表，编号顺延。
2. **删除需求**：不删行，把优先级改成「已废弃」并注明原因。
3. **改变已有需求的语义**：新增一条 `FR-XXX-0NN`，标注「替代 FR-XXX-0MM」，同时补一篇 ADR。
4. **优先级调整**：只改优先级列，不换编号。编号是稳定标识，阶段会变。
5. 每次里程碑结束做一次需求复盘：哪些估错了、哪些其实没人用。

## 附录 A：术语

| 术语 | 含义 |
|---|---|
| 空间 / 工作空间（Workspace） | 租户边界。一个空间的数据对另一个空间完全不可见 |
| 项目（Project） | 空间内的协作单元，文档的容器 |
| 文档（Document） | 一篇可编辑的内容，属于某个项目 |
| 块（Block） | 文档的最小结构单位，实时协同的基本单位 |
| 版本（Revision） | 文档在某次「发布」时的不可变快照 |
| 快照（Snapshot） | 协同编辑状态的完整备份，用于加速恢复 |
| ADR | Architecture Decision Record，架构决策记录 |
| Outbox | 事务性发件箱：保证「业务写库」和「事件发布」原子性的模式 |

## 附录 B：第一版到底能砍到多小

如果 M2 想更快看到东西，最小闭环只需要 **5 个功能**：

1. 注册登录（FR-AUTH-001/003/004）
2. 建空间 + 邀请一个人（FR-WS-001/003）
3. 建文档并写 Markdown（FR-DOC-001/003）
4. 对方能看到并评论（FR-CMT-001）
5. 一切都记进审计（FR-AUD-001）

这 5 条走通，项目就「活」了。剩下的所有东西都是在这个骨架上长肉。
